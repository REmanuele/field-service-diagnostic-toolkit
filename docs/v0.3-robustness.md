# v0.3 proposal — Error handling and automated tests

This is a **proposed incremental change** on top of the existing v0.2 release. The `--redact` and owner-only atomic report export behaviors are unchanged.

## Changes

- `run_command()` returns a failed check, rather than raising, when a process cannot start due to an `OSError` (for example, `PermissionError`) or its output cannot be decoded.
- `read_dns_servers()` gracefully handles missing, unreadable or undecodable `/etc/resolv.conf` and only parses exact `nameserver` directives.
- `read_memory_usage()` returns `unknown` rather than a misleading percentage when `MemAvailable` is absent or inconsistent with `MemTotal`.
- Ten additional unit tests cover these cases and the redacted report behavior during a resolver-file error.
- GitHub Actions runs the full test suite on Ubuntu using Python 3.10, 3.12 and 3.13 for pushes and pull requests.

## Run tests

Linux/macOS:

```sh
python3 -m unittest discover -p 'test_*.py' -v
```

Windows PowerShell:

```powershell
py -3 -m unittest discover -p "test_*.py" -v
```

The existing POSIX-permissions test is expected to be skipped on Windows. It runs on Linux CI.

## Limitations

- An unreadable resolver configuration produces an empty detected DNS-server list; it does **not** prove that the system has no DNS configuration.
- Network checks (`ping`, DNS) may generate traffic; a failure does not necessarily imply loss of Internet connectivity.
- `--redact` is best effort, not guaranteed anonymization. Do not publish real reports without manual review.
- No changes are made to service configuration, firewall rules, credentials, scheduling, or running Linux systems.
